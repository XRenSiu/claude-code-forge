# agent-map — <仓库名>

> 这份文件回答一个无上下文的实现者上手时必问、而卡里从来没有的四个问题：
> 怎么跑测试、怎么构建、哪个目录管什么、哪里不能碰。
>
> 四条纪律（`verify_agent_map.py` 检）：
> 1. **命令必须真能跑**。`--probe` 会逐条执行并记退出码；跑不通的命令比没有命令更糟——
>    实现者会照着它试三次，然后自己去猜。
> 2. **陷阱必须有来路**。每条"已知陷阱"指向一次真实失败（ledger 行 / issue / commit），
>    没有来路的条目不存在。想出来的陷阱是噪音，从失败里来的才是资产。
> 3. **占位符不算填写**。`<...>` / TODO / 待补 会被拒。
> 4. **引用已有的规则，不再抄一份；引用要能核对**。仓库的 CLAUDE.md / `.claude/rules/` 里已经写过的
>    禁区和陷阱，这里一行引用即可：`file:CLAUDE.md#"原文里的一句"`。原文必须仍逐字出现在那个文件里——
>    源头改了措辞，这一行就红，地图跟着改。只写 `file:CLAUDE.md` 或 `#L42` 也能过，但会被 flag：
>    源头挪一行、换个说法，这里发现不了，两份就悄悄分叉了。
