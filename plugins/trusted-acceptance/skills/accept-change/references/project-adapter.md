# 项目适配：先提案，跑通后才算接入

只在项目未接入或适配有缺口时读。第一版保持一个 accept-change 入口，不额外建立 setup Skill 或 Agent fleet。

1. 读取现有 CI、启动说明、测试脚本、数据/身份准备、架构规则、健康与清理入口。输出“可复用 / 需修补 / 未支持”。不要先生成一套重复框架。
2. 选择一个可运行模块，在干净环境启动、准备合成数据和独立身份、检查健康、运行已有检查、清理；保留实际记录。环境变量只记录名称与密钥引用，不保存真实密钥。
3. 按 `assets/project-adapter.example.json` 提出适配包；recipe/check ID 必须映射到已审阅的实际固定脚本，不能通过候选字段拼接 shell 命令。candidate 安装和构建也可能执行任意代码，必须置于低权限运行区。
4. 标明平台、API、缓存、身份等能力范围。Web/Electron/移动端可共用协议，不能共用未经验证的启动和采证声明。
5. 维护者批准控制仓库、执行身份、证据库、发布器与门禁规则，并以好/坏候选重复跑通。缺权限时输出具体部署提案，不获取管理员权限或关闭保护求安装成功。

适配 JSON 是提案模板，本包不会执行其中的 recipe，也没有把它注册到真实控制服务。冻结前需要检验：脚本确实存在、能重复启动/退出、数据可清理、身份隔离、必验项映射、证据类型与脱敏/保留策略、超时和预算。

项目接入的最小验收：合法实现能通过，UI 假成功但后台仍泄漏能失败；删检查、exit 0 假命令、假报告、旧报告套新候选、取消后的迟到结果、环境未启动、损坏证据与 skip 都不能放行。需要实测权限边界，不把本地 fixture 测试当作部署验证。

与现有能力衔接：AI-DLC/Forge/项目 Harness 继续实现、自测和提交新候选；已有 acceptance-fleet 可提供审查发现，但其报告属于输入，不能取代受保护逐项检查与签发。PostHolder 可提交任务/接收结果，在外层维护状态和预算；不在本 Skill 中新增调度平台。
