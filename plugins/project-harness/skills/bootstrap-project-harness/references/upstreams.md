# Upstream methods

Implementation is original. The following pinned studies informed the design; no external runtime is installed and no upstream code is copied. The development repository's upstreams.lock.json records exact revisions and adoption points.

- github/awesome-copilot: survey existing assets, choose minimal additions, report adoption and drift.
- OpenAI harness-author / openai-agents-js: right-sized ownership boundaries and verification prerequisites before independent checks.
- walkinglabs/learn-harness-engineering: separate survey/templates/validation; replace unmarked truncation and structural success with explicit scope and real execution.
- Intense-Visions/harness-engineering: incomplete analysis, nonzero denominator and unavailable-check status.
- storytold/craft-anything: version-bound evidence, per-claim verdicts, explicit unknowns.
- EveryInc/compound-engineering-plugin: choose minimal prevention for verified failures; test allowed and rejected cases.
- ChristoSmuts/frontend-harness-engineering: declarative output plans and independent host selection; writer implemented here with stale-hash and recovery handling.
- anthropics/skills: paired task evaluation and trigger testing; require a complete scheduled matrix and never substitute characters for token counts.

The original design document is a proposal; test reports in validation/ record which parts have actually been exercised. Host activation and downstream business improvement require additional live evidence beyond deterministic tests.
