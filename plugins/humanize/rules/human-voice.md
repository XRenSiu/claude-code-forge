# human-voice：写给人看的东西，按人的方式组织

适用：技术方案、设计文档、ADR、复盘、README 的叙述部分、给同事的邮件与评审意见——凡是**一个人要从头读到尾**的东西。
不适用：API 参考、配置表、命令速查、commit message、代码注释（那些本来就该是表）。

读者读不懂 AI 写的东西，不是因为词难，是因为**每句话都对、但句与句之间没有一条线**。下面的约束全都在修那条线。
词汇级的禁令放在最后，因为研究表明词汇级约束在长对话里比"定义式"约束更耐久——但它只是地板。

## 文档形状

- **第一段是触发事件，不是背景。** 写促成这份文档的那个具体事实（一次故障、一个数字、一个被拒的 PR），不写
  "随着业务发展 / In today's landscape"。读者看完第一段必须知道"出了什么事、你打算怎么办"。
- **结论先行。** 推荐 / 决定在前 3 段之内以一句话出现。论证跟在结论后面，不铺垫在前面。
- **杀掉替代方案。** 方案类文档必须写"没选 X，因为 <一个具体原因>"，至少一个。现状永远算一个替代。
- **列表只放真正并列、无序的东西。** 各项之间有因果、前提、取舍关系的，写成段落把关系说出来。
  四条"**加粗标签**：一句空话"的列表等于没写。
- **不写总结段。** "总之 / In conclusion" 段几乎总是复述上文。结尾放下一步动作，或者放还没想清楚的那个点。
- **不叙述文档自身。** 不写"本节将介绍 / In this section we will"。标题承担结构。
- **标题是主张片段，不是分类名。** "为什么不用 Kafka" 而不是 "技术选型"。

## 段落与句子

- **旧信息在前，新信息在后。** 每句开头接上一句已经出现的东西，把新东西放句尾。读者跟丢的位置，几乎都是一句话
  开头冒出没见过的名词。
- **主语是做事的人或系统，动词是它做的事。** "网关在 500ms 后断开连接"，不是"连接的断开由网关在超时后进行处理"。
  中文删掉"进行 / 开展 / 加以 / 予以 + 名词"的壳；英文不写 "the implementation of X enables"。
- **句尾不挂没论证的收益。** "…，确保系统稳定性" / "…, enhancing overall efficiency" 这种尾巴要么升格成一句并给证据，要么删。
- **一段一个主张，第一句就是那个主张。** 只读每段第一句也能跟上全文。
- **句长要有起伏。** 连续五句都是 25 字左右就是模板。每 300 字至少一句不到 12 字。
- **靠内容衔接，不靠路标。** 删掉句首的"首先 / 其次 / 此外 / 值得注意的是 / Furthermore / Moreover"。删掉之后两句接不上，问题在内容。
- **关键术语重复用，不轮换同义词。** "缓存"就一直叫"缓存"。

## 判断与立场

- **说"会"，不说"可能会"。** 对冲只留给真不确定的地方，并且说清不确定的是什么、打算怎么消除。"可能存在一定风险"是零信息。
- **有人在负责这个判断。** "我建议 / 我没选 / 我最担心的是"是正常的。通篇无人称、无立场的方案读起来像没人写过它。
- **形容词换成数字或例子。** "显著提升性能" → "P99 从 1.4s 到 120ms"；"复杂度较高" → "要改 3 个服务的写路径"。
- **没做过的调查不要伪装成做过。** 数字必须真有来源；没有就写"没测，估计量级在…，上线前会测"，或标 `[需核实]`。
- **有字面说法就用字面说法。** 不把 "a parameter worth varying" 写成 "a dial worth turning"；不自造术语当通用术语（"load-bearing""the unlock"）。

## 一眼就能改掉的表层

- 不要 emoji、不要满篇加粗、不要 Title Case 标题、不要"不是 X 而是 Y / It's not X, it's Y"连用、不要什么都凑三个。
- 中文不用：赋能 / 抓手 / 闭环 / 至关重要 / 不可或缺 / 扮演着重要角色 / 为…奠定基础 / 值得注意的是 / 综上所述 / 随着…的发展。
- 英文不用：delve / leverage / robust / seamless / crucial / pivotal / landscape / tapestry / it's important to note / in today's / furthermore / moreover.
- 中文不写翻译腔：不用物理动作动词写心理过程（"接住反馈" → "收到"）、不用抽象名词做主语加评价词收尾、有译法的英文词要译。
- 破折号每千字不超过两个。

## 不要为了"像人"做的事

不加口语词、语气词、笑话、错别字、emoji、人设。在技术语域里这些是**新的 AI 味**，还损失读者信任。
"像人"来自判断和具体，不来自随便。

## 检查方式

写完跑 `humanlint.py`（本插件 `skills/humanize/scripts/`）看表层指标；真正的验收是让一个没看过写作意图的读者
（`cold-reader` agent，隔离上下文）逐段说"读到这里我以为你要讲什么"，跟丢两处即打回。方案类另跑 `verify_techdoc.py`。
