# 各 focus 的问题清单（Detective Loop 的起点，不是走完的清单）

## security（默认对抗式：假设这段代码造成了线上事故）

- 每个从请求 / 文件 / 环境读入的值：在哪校验？校验能被绕过吗（类型、长度、编码、路径穿越）？
- 每个访问对象的操作：谁校验了 current_user 对该对象的权限？middleware 真的覆盖这条路由吗（grep 路由表）？
- 拼进 SQL / shell / HTML / URL / 正则的字符串：参数化了吗？
- secrets：日志里、错误信息里、URL 里有没有 token / 密码？新增的 env 读取有默认值吗（默认值是不是危险值）？
- 加密 / 随机：`Math.random` 用在安全上下文？哈希盐？
- 并发：check-then-act 之间有没有锁 / 幂等键？
- 新增依赖：包名在注册表存在（防编造）、许可证、已知 CVE。
- 删掉的代码：删的是不是一个检查（`git log -p` 看它什么时候加的、为什么）。

## logic

- 状态变更的顺序：失败中途会留下半截状态吗？事务边界在哪？
- 异常路径：catch 里吞了什么？重试会重复副作用吗？
- 边界：空、0、负、超长、Unicode、时区（本地时间 vs UTC）、闰秒级别的不用管。
- 条件反转、off-by-one、`==` vs `===`、浮点比较、可变默认参数。
- 调用方：diff 改了签名 / 语义，所有调用点都跟着改了吗（grep）？
- 测试：新测试断言了行为还是断言了实现？有没有空断言、只测 happy path？

## perf

- 循环里的 I/O / 查询（N+1）；大集合无分页；同步阻塞调用在服务端；
- 没有清理的定时器 / 监听器 / 订阅；缓存无失效；
- 热路径上新增的分配 / 序列化；不度量就不说"慢"——降到 P2 并注明未测。

## style（只在 `--focus=style` 时报，且只报影响可维护性的）

- 命名与意图不符；魔法数字；死代码；重复块；注释与代码矛盾。
- 纯格式问题不报（那是 formatter 的事）。

## 通用的下一步选择（Detective Loop）

看到 `import { foo } from '../bar'` → 读 bar；看到一个函数被改 → grep 调用点；看到一个检查被删 →
`git log -p -S'<检查>' -- <file>`；看到 mock → 看被 mock 的真实实现是否与 mock 语义一致。
预算 ~20 次工具调用；对一个 hunk 形不成意见就放弃它。
