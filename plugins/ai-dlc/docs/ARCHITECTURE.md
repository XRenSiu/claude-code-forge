# AI-DLC 架构

> 一条产研自闭环的流水线：世界 → 本体 → 契约 → 标准 → 计划 → 实现 → 验收 → 交付 → 学习。
> **每一步的产物要么能被脚本检，要么被一道只能人签的门挡住，没有第三种。**
> 失败按层回流而不是原地重试；账本只增不删；线上逃逸的缺陷回到它该回的那一层。

这份文档自包含：读完它就够了解这套东西是什么、怎么转、怎么用、现在还缺什么。
它不讲这套东西怎么变成今天这样，也不讲它跟别的方法论像不像——那些与"它现在是什么"无关。

---

## 1. 它要解决的问题，和由此推出的一切

**AI 的产出速度已经超过人的验证速度。** 一个人可以在一小时里拿到十个看起来都对的实现，
却没有一小时去逐个验证它们。所以这条流水线的目标函数不是"加快产出"，是**降低验证成本**。

这一句是全部设计的唯一前提。判断一条新规则该不该加，就问它：**它让人少验一点，还是多验一点？**

由它直接推出三件事：

- **能机械判的必须机械判**，因为脚本的验证成本接近零。判据要写成脚本能跑的形状，跑不了的要说自己跑不了。
- **不能机械判的必须显式交给人，并且只交一次**。散在各处的"你看一眼"不是验证，是骚扰；
  攒到最后一次性交出一万行也不是验证，是走过场。
- **人验过的东西必须冻住**。验证的价值在于它之后的东西建立在它上面；如果判据在被批准之后还能改，
  那次批准就白付了。

贯穿全文的一条极性，是上面第三条的机械形式：

> **一个靠遗漏就能打开的门不是门。**

凡是"没填 / 没跑 / 没标 / 没签"，一律走**严**的那条路。缺省的体量档位是最严的一档；
手设的档位换不到任何豁免；分析器跑不起来记"未检"不记"通过"；审查没跑完记"未检"不记"没发现问题"。

## 2. 五个部件

```
              ┌────────────── ① 主干：做什么，按什么顺序 ──────────────┐
              │  intake → track → issue → branch → contract → g2 →      │
              │  cards → implement → acceptance → pr → review → g3 →    │
              │  merge → release → archive                              │
              └─────────────────────────────────────────────────────────┘
                        ▲                                    │
   ② 三个正交旋钮：跑多少 │                                    │ ③ 六个环：没一次做对怎么办
      广度 跑哪些阶段[强制]│                                    ▼
      测试量 验多少 [下界] │      card_retry · ratchet · acceptance_ratchet
      深度 产出多细 [声明] │      review_loop · lifecycle · hill_climb
                        │                                    │
              ┌─────────┴────────────────────────────────────▼─────────┐
              │ ④ 三道人签的门：G1 世界裁决 · G2 判据冻结 · G3 例外复核 │
              │    旋钮拧不掉它们，环也升级不过它们                     │
              └─────────────────────────────────────────────────────────┘
                                    │
              ┌─────────────────────▼───────────────────────────────────┐
              │ ⑤ 两条记忆通道                                          │
              │    ledger.md 记「已经错了什么」                          │
              │    notes.md  记「含糊处当时选了什么」                     │
              └─────────────────────────────────────────────────────────┘
```

**① 主干**是十五个阶段的**依赖顺序**，不是流程规定。哪些能并行、先做哪个是执行者的份额；
顺序只在它是依赖（没有 issue 就没有 `Closes #N`）或不可逆（push、merge）时才出现。
主干由脚本拥有：每次推进都对着状态文件检前置条件，**不对着执行者的说法检**。

**② 三个旋钮**让同一条主干伸缩。没有旋钮，三行 bug 修复也要走完全程，成本高到没人愿意用，
于是整条流水线被绕过——**一条被绕过的流水线抬不高任何人的下限**。三个旋钮互相正交：
"完整文档 + 最少测试"是合法组合，测试量不该被文档详细度绑架。但**三者的强制力不同，文档如实标注**（见 §5）。

**③ 六个环**处理"没一次做对"。每个环共用一份契约：生成者与验证者必须是两个东西，
停机条件四键齐全（成功 / 收敛 / 预算 / 不可能），预算可解析。环负责在原地多试几次，
但**它判不出"再试也没用"的时候就得交出去**——那是 §6 的收敛检测。

**④ 三道门**是唯一只能人签的东西。它们不在旋钮的可达范围内，也不接受环的自动升级。
这是整套设计里唯一不谈效率的地方：**门存在的意义就是让人付出验证成本，而不是替他省掉。**

**⑤ 两条记忆通道**回答两个不同的问题，缺一条就有一类问题永远查不出来。
账本回答"哪一层病了"，它记的全是**已经发生的错**。日记回答"当初为什么往那边走"，
它记的是规格含糊处执行者**当场做了什么选择**——那件事发生时没人认为是个错，
所以账本里永远没有它。一次逃逸缺陷的因果链走到头如果落在"当时按默认理解填了"，只有日记能答。

## 3. 主干：十五个阶段

```
intake → track → issue → branch → contract → g2 → cards → implement
       → acceptance → pr → review → g3 → merge → release → archive
```

状态文件 `.aidlc/<slug>/state.json` 是这次运行的**充分统计量**：只留状态，不留历史。
它由 `aidlc_state.py` 拥有，**不手改**。每次 `advance <阶段>` 检查前置条件，不满足就拒绝并列出缺什么：

| 进入 | 必须已成立 |
|---|---|
| `track` | 标题已设 |
| `issue` | 轨道 ∈ {psl, task}；PSL 轨还要 G1 已过 |
| `branch` | issue 号已设 |
| `contract` | 分支名已设 |
| `g2` | 契约文件存在**且过 v2 校验** |
| `cards` | G2 裁决为 pass ∧ 锁文件存在 |
| `implement` | G2 裁决为 pass ∧ 锁文件存在（**cards 被网格跳过时也要**）∧ 锁已是 l5 且锁里有测试 ∧ 红基线经 `--verify` ∧ `lint_cards.py` 对 `cards.dir` **当场跑过且过** ∧ 至少登记一张卡 ∧ 锁未被动 |
| `acceptance` | 所有卡 done 或 skipped ∧ 没有欠着的失败报告 ∧ 按档要求的校准报告过元闸 ∧ 锁未被动 |
| `pr` | 整体验收的 final-state.json **读出来**是 DONE、没有跑不完的审查、声明了阈值就有 `meets_done_when.py` 的 met；或有留痕的跳过理由 ∧ 红→绿证据为 green ∧ 没有欠着的失败报告 ∧ 锁未被动 ∧ 分支历史里改过被锁文件的提交都带着变更提案 |
| `g3` | 评审出口已记录，且 done 的出口有 `pr-poll.sh` 写下的裁决文件（exit 0 / 10） |
| `merge` | G3 需要时裁决为 pass（G3 不需要时同 `g3` 行）∧ 锁未被动 ∧ 锁历史干净 ∧ 网格跳过了整体验收时有 pre-review 发现文件 |
| `release` | merge sha 解析得到且已在 branch.base 里 |
| `archive` | 同 `release` ∧ 发布完成（release.notes 里**有 post-deploy 行**，tag 在 git 里指着 merge.sha）或有留痕的跳过理由 |

越级需要 `--force --reason`，而豁免被写成一条 waiver 记录（状态 + 账本），复盘时会被数出来。
**没有无声的跳过**——这是"一个靠遗漏就能打开的门不是门"在状态机上的形式。

**前置条件是文件，不是 flag。** 曾有四个布尔由引擎自己 `set`（`cards.lint_passed`、`acceptance.evaluation_result` 只查非空、
`acceptance.meets_done_when`、`release.done`）——那是执行者的说法，恰恰是这一节说不能信的东西。现在 `advance` 自己跑校验器：
G2 跑契约 v2 校验，implement 跑卡 lint，pr 读 final-state.json 与达标比对报告，archive 读发布记录里的 post-deploy 行，
并在 implement / acceptance / pr / merge 重跑锁校验——`/commit` 与 `/pr` 的预门能被裸 git 绕开，状态机绕不开。

执行图 `graph.yaml`（53 节点 · 69 边）把同一件事声明成数据：节点带边界身份
（读什么 / 不许读什么 / 写什么 / 有什么权限），边带类型与守卫，回边标明属于哪个环。
`graph check` 让它与状态机的阶段列表**互相断言**——图和代码互为对方的测试。
`verify_graph.py` 另外检五条性质：写范围有界、去掉回边后是 DAG 且每个圈归属一个环、
评估者到实现者的边只能携带修复提示、人节点必须声明恢复绑定、扇入必须有合并规则。

## 4. 三道门

| 门 | 何时 | 人看什么 | 脚本强制什么 |
|---|---|---|---|
| **G1 世界裁决** | 推导产物之后、issue 之前（仅 PSL 轨） | 推导出的本体提案 / 工作流 / 形态草案，以及 N 次独立推导的分歧集 | pass 要求推导目录存在；reject 必须归因（推导错了 / 规律错了），归因决定回流到哪一层 |
| **G2 判据冻结** | 契约写完、拆卡之前 | `done_when.yaml`：什么算做完 | pass 要求锁文件存在；契约必须先过 v2 校验；签完即冻结 |
| **G3 例外复核** | 验收之后、合入之前 | 人判类 AC、失败报告、假设台账、B 档告警 | 有人判 AC 的需求默认触发；契约里有 `kind: human` 的 AC 时 `gates.g3.required=false` 被拒，关掉它要显式设置并留痕 |

**门与"人做的动作"不是一回事。** 执行图里标 `human` 的节点有五个，但只有三个是门。
判别标准只有一条：**有没有一个可以被签、被拒、被计数的判决**。
G1/G2/G3 有裁决对象、有签字人、有 verdict、能被复盘统计；
合并代码和审阅调参提案是人做的动作，没有 verdict，也不进门的统计。
把五个都当成门，或以为文档漏写了两道，都是读岔。

签字必须是人。代签只在有明确授权记录时成立，且授权本身要写下来。
自治程度（每步都问 / 到门为止自动 / 到失败为止自动）整个流程只问一次，答案记进状态、跨会话有效——
但**三档都不代签门，失败也永远中断**。

## 5. 三个旋钮

| 旋钮 | 调什么 | 谁强制 |
|---|---|---|
| **广度** | 这次跑哪些阶段 | `next_allowed` / `prereqs` **强制**；`verify_sizing.py` 九条 lint 核验 |
| **测试量** | 这次验多少 | **下界**：`derive_counts.py --strategy`，低于地板退出 4 |
| **深度** | 每个阶段产出多细 | **只是声明**。没有任何脚本能判"这份文档够不够细" |

第三行是有意如此，不是没做完。**不许把声明写成闸**：报出一个没人验过的"通过"，
比不报更坏，因为它以证据的形状到达。

### 广度是网格，不是散在代码里的 if

`sizing.yaml` 用四个**可数的量**定档——改动文件数、AC 条数、人判 AC 条数、轨道，没有形容词：

| 规则 | 命中条件 | 档 |
|---|---|---|
| SZ-01 | PSL 轨 | L |
| SZ-02 | 人判 AC ≥ 1 | L |
| SZ-03 | AC ≥ 8 | L |
| SZ-04 | 改动 ≥ 15 文件 | L |
| SZ-05 | AC ≤ 2 且改动 ≤ 3 文件且 TASK 轨 | S |
| SZ-06 | 兜底 | M |

档位定下之后，`stages:` 网格说这一档跳哪些阶段（S 跳 `cards` 与 `acceptance`），
`never_skippable` 说哪些阶段任何档都不能跳——**三道门在里面**，广度旋钮拧不掉门。

三重极性保证跳过必须被挣来：

1. 缺省是 M，缺省不跳任何阶段；
2. 跳过只认**推导来的**档位，手设档位一扇门也打不开；
3. `never_skippable` 在最外层兜底，即使网格被改错也拦得住。

每个被跳的阶段写一条带理由的账本行，复盘时按档分桶数逃逸缺陷——**分档定得对不对，
由下一次逃逸缺陷回答，不由拍脑袋回答**。

`verify_sizing.py` 的第七条 lint 直接 import 真的那份 `next_allowed`，把每一档的剩余路径走一遍。
自己写第二份判定迟早与真的那份分叉，而分叉出来的那份会说"网格没问题"。

**定档可以早，也可以改。** AC 数可以在 issue 阶段就从 issue 正文里数出来（数字与它的来路由同一次读产生，
issue 不合格就拒绝取数）；文件数要等有 diff。缺一个量的规则不会命中，而 S 的唯一入口需要文件数——
所以**早定档在结构上只能把你推向 L 或留在 M，给不出 S 的豁免**。这不是额外加的限制，
是这组规则本来的形状，`needs:` 字段把它写成声明、lint 核它与命中条件一致。
跑到一半可以重新定档，但**只能改尚未开始的阶段**：一次已经付过的 G2 不会被追认为"其实不用签"。

### 测试量是地板不是天花板

`minimal` 的地板 = 机械 AC 条数（每条需求一个采样点）+ 观察边界数（每个边界至少一条正常路径）。
`standard` 翻倍（正常路径之外要有异常路径）。`comprehensive` 不设算术地板——
它的下界是"五层金字塔每层都非空"，那是判据，不是一个数。
写多了不报错，写少了退出 4，且这个退出码与"契约里根本没写测试"的退出 2 分开：
**"量不够"和"配置错"是两种失败**。

## 6. 六个环与收敛

每个环共用一份契约（`loops.yaml`）：

| 环 | 谁生成 | 谁验证 | 尺度 | 卡住了升到哪 |
|---|---|---|---|---|
| `card_retry` | 实现者 | 验收 | 分钟 | 方案层 |
| `ratchet` | 执行者 | 评估者 | 小时 | 方案层 |
| `acceptance_ratchet` | 实现者 | 综合裁决 | 小时 | 任务层 |
| `review_loop` | 修复者 | 人类评审者 | 小时 | 任务层 |
| `lifecycle` | 编排者 | 人（G3） | 天 | 世界层 |
| `hill_climb` | 调参 | 人（审 PR） | 天 | 人 |

契约的三条硬约束：**生成者 ≠ 验证者**（否则不存在评估）；**停机四键必须显式**
（成功谓词 / 收敛信号 / 预算上限 / 不可能判决，值可以是 null 但不能不写）；**预算可解析**
（指向路由表里的一个数，不是散文）。

### 什么时候"再试也没用"

每个失败键保留最近若干次的指纹与分数，脚本判三种信号：

- **同指纹连续 2 次 = repeat** —— 一模一样的失败重现，说明这一层没有进展。指纹要的是「同一个失败」不是「同一段字节」：
  `--evidence` 先归一化（行号 / 十六进制 / 时间戳 / 临时路径抹平）再取摘要，否则同一个失败永远不会「重复」；
- **周期 2–3 的往复 = oscillation** —— 在几个相似解之间来回，那是方案层的权衡没定；
- **分数连续若干轮不超过历史最佳 = plateau** —— 允许一次探索性重写，再不涨就升级。

第四种不是检测出来的而是被报告的：**评估者**判"在当前契约下不可能"。
只有评估者能报，实现者报被拒——否则"做不到"会变成实现者绕开契约的通道。

**收敛 ≠ 正确。** 三个信号都稳但产物差，结论是换方案，不是再迭代一轮。
任一升级都会置上"欠一份失败报告"的标记，而结束会话前的清洁检查会拒绝在报告没写时收工。

## 7. 失败往哪回

五个层，由内向外：**卡 ⊂ 方案 ⊂ 任务 ⊂ 本体 ⊂ 世界**。

`fail --signal <信号>` 读路由表（16 条规则），给出候选层、处理者、动作、该层计数与预算余量、
指纹重复次数、是否升级。原则只有一条：**失败先归层，再决定谁处理**——
不在实现层重试世界层的错，因为那样只会烧完预算再回到同一个问题。

预算按轨道分：单卡重试 3（**按卡计**：卡 A 烧掉的重试不动卡 B 的预算；层计数仍全局累加，那是复盘看的分布不是预算）；
方案层回流 2；任务层 PSL 轨 2、TASK 轨 1；本体层 1；**世界层不设上限**——本来就该停下来交给人。

任一层预算耗尽时产出失败报告：候选层 + 证据 + 已排除的可能 + 建议回退点。
那份报告是 G3 的输入——**人看报告，不看原始日志**。已排除的可能由决策迹预填，
所以"这条路我们试过了"不需要人重新考古。

## 8. 契约：一个产物只有一个生产者

```
需求原文 ─psl─▶ PSL ─psl-derive─▶ derived/ ─G1─▶ 签字版形态草案(sha256)
                                                    │
代码 ─dos-extract─▶ dos.yaml ◀──── 对账（人，记在 G1 记录里）
失败记忆 ─invariant-extract─▶ 不变量卡 ─┐
                                        ▼
需求 / 形态草案 ─issue─▶ issue ─donewhen-extract─▶ done_when.yaml ─G2─▶ .done_when.lock
                                                        │
                          plan-cards ◀──────────────────┤
                              │ cards/                   │
                              ▼                          ▼
                        implement ─commit─▶ diff   test-suite-generator + spec-compile
                              │                     ─▶ tests/ ─calibrate─▶ 校准报告
                              │                          │ 二次锁
                              └────▶ acceptance-fleet ◀──┘
                                          │
                                pr ─▶ review-loop ─▶ merge ─▶ release ─▶ 归档
                                                                  │
                                          逃逸缺陷 ─▶ retro ─▶ 变更提案 → 世界 / 本体 / 契约
```

**契约只有一种 schema。** `done_when.yaml` 以 AC 为单位：每条 AC 要么是机械的
（观察边界 / 前置条件 / 期望结果），要么是人判的（陈述 / 裁决人 / 证据形式）。
G2 签的就是这份 AC 清单。形状不对就冻结不了——`advance g2` 会先跑校验器。

**两段锁。** G2 锁判据；测试写完之后再签一次，把测试与清单一起锁上——**l5 锁是 `advance implement` 的前置**，
锁里没有测试就不能开始实现，红基线也要先经 `capture_red_baseline.py --verify`；`advance pr` 再读 `verify_red_green.py` 的 green。
锁的时候连**执行契约的闸脚本本身**一起冻——否则契约冻了、量它的那把尺没冻。
之后任何被锁文件出现在 diff 里，同一个 diff 必须附一份变更提案，否则提交与 PR 的预门都拒。

**测试不是实现者写的。** 判据先于代码，测试由非实现者写，写完锁上。
改契约或改测试只能走变更提案——**绝不用改测试的方式让测试过**。

## 9. 验收：三档，加上信息隔离

| 档 | 检什么 | 效力 |
|---|---|---|
| **A 机械** | 测试 / lint / 类型 / 密钥扫描 / 文件白名单 / 锁 / 新增依赖 / 需求覆盖 / 隐藏集 / 契约硬命中 / 有复现的缺陷 / 结构（复杂度增量 · 重复块 · 依赖方向）/ 审查完成度 | **一票否决** |
| **B 结构** | 复杂度 / 重复 / 公共 API 变更 / diff 体量 / 规格漂移 / 作弊软命中 / 跨制品术语漂移 | 超阈值告警，有界可进 |
| **C 判断** | 人判 AC / 架构意图 / 可读性 | 请求人工（G3） |

A 档里有两条特别的：**结构闸**在分析器跑不起来时退出"未评估"，
**审查完成度**在审查产物缺完成标记时同样退出"未评估"。两者都**不是通过**（见 §13 规则 14）。

**评估者与被评估者必须分离，否则不存在评估。**

- 实现者只拿到：一张卡 + 状态摘要 + 该卡的 AC 子集 + 红基线。看不到评审判据、隐藏集、别的卡。
- 评审产物只给人和综合裁决者；回到实现者的是修复提示（位置 + 改法），不含评审者身份与置信度。
- 校准用的隐藏变体集放在实现者读不到的地方。
- 评审环里的验证者与修复者是两个上下文。
- 有跨供应商评估器时，用在最容易同源盲区的两个槽：对抗式代码审查与作弊检测；
  分不到就把"同源"这件事记下来，不假装它不存在。

**"达标了没有"由脚本比对阈值得出，不由评估 agent 宣布。** 那把尺子是 `meets_done_when.py`：契约的 `behavior.thresholds`
逐条对 qa 投影出来的测量比，没量到的记未评估；它的报告经 `acceptance --meets` 进状态，`meets_done_when` 本身不可 `set`。

**审查者子集同理。** M 档只跑两个审查者是一次豁免，豁免只认推导来的档位：`size_source` 是缺省或手设时六审全跑——
不跑 `size` 就少四个审查者，是一扇靠遗漏打开的门。

## 10. 两条记忆通道

| 通道 | 记什么 | 回答什么 | 形态 |
|---|---|---|---|
| `ledger.md` | 每次失败、被拒的修复、路由决定、门的裁决、豁免 | 哪一层病了 | 只增不删 |
| `notes.md` | 规格含糊处当场做的选择 | 当初为什么往那边走 | 只增不删，四个固定格子 |

日记的四个格子分工明确：**解释**（含糊处我按什么理解做的）、**偏离**（有意没照做，以及为什么）、
**权衡**（考虑过的替代方案）、**待答问题**。前三格是可固化的知识，**第四格明确不晋升**——
待答问题是研究项，不是规则。

门禁之前，日记里的每一行**逐字**呈现给签字人：不改写、不做"有趣度"筛选。
被筛掉的那一条就是下次撞的墙。签字人唯一要做的分类是"哪几条该变成下一轮的规则"。

**晋升的规则下一轮才生效。** 写在盘上，下一次运行启动时编译进来。
跑动中改规则会让前面已经批准过的门失去意义——你当时批准的是另一套前提。
可复现优先于立刻变聪明。作用域只有项目一级，没有团队与组织通道：
跨仓库的提升是人做的事，不是脚本的权限。

**非对称回滚。** 产物（代码、卡、PR、契约版本）可以回滚；
判据、失败记录、被拒的修复、路由决定、豁免**不回滚**。被评审推翻的裁决也保留原记录。

账本每一行同时写进决策迹 `trace.jsonl`，事件之间用封闭集的类型边相连：
`caused_by` / `decided_by` / `supersedes` / `implements` / `references` / `depends_on` / `rejected_alternative`。
只增日志只能向后指，所以因果边写成**效果指向原因**。
于是"这条 AC 为什么改"、"改它波及哪些卡与提交"、"逃逸缺陷的因果链有多深"
从考古变成一条查询。不上图数据库——迹是证据，不是控制状态，损坏不影响预算与迁移。

归档时状态、账本、日记、迹、契约与锁一起复制到 `specs/<slug>/`，那是复盘的唯一数据源。
运行时目录 `.aidlc/` 是状态不是交付物，**不入库**。

## 11. 二十八个 skill、五个 agent

九环加一根脊柱。**脊柱不做任何一环的活**，只做五件事：持有状态、记账、路由失败、
把三道门编译成"不跑就推进不了"、把图与环声明成数据。

| 环 | 回答的问题 | skill | 机械预门 |
|---|---|---|---|
| **R0 世界** | 这个产品为什么这样运转 | `psl` `psl-derive` | `verify_psl.py` `verify_derived.py`；**G1** |
| **R1 本体** | 系统里有什么、叫什么、什么不可违反 | `dos-extract` `invariant-extract` | `verify_dos.py` `verify_card.py` `verify_agent_map.py --probe`（命令逐条实跑）`verify_vocabulary.py` |
| **R2 契约** | 什么算做完 | `issue` `donewhen-extract` `acceptance-spec` | `verify_issue.py` `verify_done_when.py` `validate_done_when_v2.py`；**G2** |
| **R3 标准** | 判据怎么被机器执行 | `test-suite-generator` `spec-compile` `calibrate` | `derive_counts.py` `verify_compile.py` `verify_calibration.py`；二次锁 |
| **R4 计划** | 怎么拆成无上下文可做的卡 | `plan-cards` | `lint_cards.py` `slice_agent_map.py` |
| **R5 实现** | 按卡做、按卡提交 | `implement` `commit` `ratchet` | `verify_commit.py`（白名单 · 锁 · 密钥）· 指纹升级 |
| **R6 验收** | 三档验收，谁一票否决 | `acceptance-fleet` + `code-reviewer` `qa-reviewer` `pm-reviewer` `spec-drift-detector` `spec-gaming-detector` + `meta-judge`；单 PR 手审 `pr-review` | `verify_structure.py` `verify_review_complete.py` `compute_score.py` `compute_confidence.py`；**G3** |
| **R7 交付** | 合入与发布 | `pr` `review-loop` `release` | `verify_pr.py` `pr-poll.sh` `verify_release.py` |
| **R8 学习** | 流程病在哪层；环的参数该不该调 | `retro` `tune` | `metrics.py` `tune.py` `apply_proposal.py`（只出 diff） |

五个隔离子 agent，各自的输入被刻意限死：`card-implementer`（单卡实现）、
`review-triager`（只读分诊）、`comment-fixer`（单线程 TDD 修复）、
`pr-reviewer`（只读审查，永不批准）、`fix-verifier`（全新上下文验证）。

每个脚本检什么、退出码什么意思，索引在 `reference.md`，**由一条冒烟期望盯着不许漏**。

## 12. 六个闭环怎么闭

| 闭环 | 起点 → 终点 | 靠什么闭合 |
|---|---|---|
| 交付 | 需求 → 合入 → 发布 | 状态机线性推进；每阶段过脚本或过门；发布后验证绿才算交付 |
| 失败 | 任一阶段失败 → 正确的层 | 路由表 + 指纹终止；失败报告 → G3 |
| 校准 | 线上逃逸缺陷 → 世界 / 本体 / 契约 | `aidlc_state.py escape` 把人的归因写成该层的一次计数、一行 escape-defects.md、一个镜像进归档的事件（复盘只读归档）→ 回答"为什么门没拦住" → 抽成不变量 → 变更提案 |
| 度量 | 归档 → 流程改进 | 复盘：基线 → 回流分布 → 提案落到能改的那一层，经门生效 |
| 标准 | 判据 → 测试 → 尺子本身 | 编译判据、证明尺子承重（变异分数 / 一致性 / 留出集 / 隔离）；未校准的标准不当证据 |
| 调参 | 六个环的迹 → 环自己的参数 | 读归档出提案（封闭 target 集），只出 diff，人开 PR 合 |

第六个是**环改环的外环**：它读其他五个环留下的痕迹，提出改这些环的参数，
但它自己的提案**永不自动生效**——路由预算、脚本默认值、修复清单的改动都要人审的 PR。

## 13. 十七条自洽规则

1. **一个产物只有一个生产者**；契约只有一种 schema，别的形态经转换后进入。
2. **判据先于代码**；测试由非实现者写，写完锁上；改契约或测试只能走变更提案。
3. **实现者看不到评估者**；评估者的输出经综合裁决或人再回到实现者，且只带修复提示。
4. **预算与终止由脚本强制**，执行者不自行维护计数器。
5. **账本只增不删**；产物可回滚，判据与失败记录不回滚。
6. **三道门只能人签**；免掉的是逐步确认，不是门。
7. **未校准的标准不当证据**；"达标了没有"由脚本比对，不由评估 agent 宣布。
8. **失败归层再处理**；同指纹重复 = 无进展 = 升级，不是重试。
9. **合入不是终点**：发布后验证绿才算交付；逃逸缺陷必须回到它该回的层。
10. **静态过审 ≠ 有效**：行为层没跑就不说"已验证"。
11. **图与环是数据，不是散文**：节点有写范围，每个圈归属一个环，人节点有恢复绑定，扇入有合并规则。
12. **收敛 ≠ 正确**：repeat / oscillation / plateau 都是"换层"的信号，不是"再试一次"的理由；
    "不可能"只能由评估者说。
13. **改流程本身要经人**：调参只出 diff，路由、脚本默认值、修复清单的改动都是 PR。
14. **声明了但没求值 ≠ 通过**。契约承诺了一条判据而求值者没跑完，结果是"未评估"，
    调用方按未检记录，**一把没跑的尺子不许报绿**。求值者是脚本还是模型不改变这条规则，
    只改变它怎么被检出来：
    - **脚本**：分析器缺席 → 独立退出码，与"通过"和"违反"都不同；
    - **模型**：一次被截断的审查留下的是一份**短而干净**的报告，与"走完全程什么也没发现"
      在字节层面无法区分。所以每份审查产物自带完成标记（状态 + 发现条数），
      两个数字产生于不同时刻，**对不上本身就是截断的证据**；缺标记走严路，不走宽路。

    一次审查最多重派一次；重派前把陈旧产物移进 `stale/` 而**不是删除**（失败记录不回滚，规则 5）；
    第二次仍不完整就记 A 档未评估，DONE 不成立。
15. **缺省不给豁免**。体量缺省是最严的一档；跳过只认推导来的档位；
    `never_skippable` 在最外层兜底；每次跳过写一条带理由的账本行。
    重定档只能改尚未开始的阶段。
16. **学习下轮生效**。晋升的规则写在盘上，下一次启动才编译进来；
    门禁前的日记逐字呈现不筛选；待答问题不晋升。
17. **强制力必须如实标注**。一个部件是脚本强制、是下界、还是仅仅一句声明，文档必须写清楚，
    **不许把声明写成闸**。理由与规则 14 同源：一个没人验过的"通过"以证据的形状到达，比不报更坏。

## 14. 怎么用

### 安装

```bash
/plugin marketplace add XRenSiu/claude-code-forge
/plugin install ai-dlc@claude-code-forge      # 之后重启 session：斜杠命令在启动时定型
```

前置：`git`、`gh`（已认证）、`jq`、`python3` + `pyyaml`。
与同名 skill 的其它插件并存时用 `/ai-dlc:<name>` 命名空间。

### 三种入口

**A · 单点使用**（不进流水线，每个 skill 独立可用）

```bash
/issue "用户可以按'上个月'这类相对时间搜索记忆"     # 结构化 issue，先给你看再建
/commit --issue 42                                  # 预门 + 自检 + 提交
/pr --issue 42 --done-when specs/x/done_when.yaml   # 预门 + 确认 + 建 PR
/review-loop 57                                     # 跟进 PR #57 直到收敛
/pr-review 57 --focus security --post               # 审别人的 PR
/dos-extract . ; /invariant-extract search          # 本体与不变量
/retro --archive specs/                             # 复盘：判据与世界的提案
```

**B · TASK 轨全流程**（形态已定的需求）

```bash
/ai-dlc "导出报表增加 CSV 六列" --track task
#  issue → branch → 契约 → 你签 G2 → 卡 → 测试 → 实现 → 验收
#  → PR → review → 你签 G3（有人判 AC 时）→ 你合并 → 发布 → 归档
```

**C · PSL 轨全流程**（体验性 / 语义模糊的需求）

```bash
/psl "用户可以按相对时间搜索记忆"              # 建世界
/psl-derive PSL-memory-time-search.md --n 3   # 推导产物 + 分歧集
#  → 你签 G1，之后同入口 B
```

轨道不靠自评：issue 里出现本体解析不了的概念（词表闭包失败）就**强制**走 PSL 轨。
自信而错的人会绕开 G1，闭包检查不会。

### 随时可问的四个问题

```bash
aidlc_state.py plan     # 这次跑几个阶段、几道人签的门、跳了什么、为什么跳
aidlc_state.py loops    # 六个环各自烧了多少预算
aidlc_state.py doctor   # 这套装置本身健康吗（建议性，从不阻断）
trace.py why AC-003     # 这条判据为什么改、谁签的、上游是哪次失败
```

### 人在哪里出现

| 时机 | 人做什么 |
|---|---|
| G1 | 三问 + 逐条回应分歧集 + 归因 |
| G2 | 确认判据、指派人判 AC 的裁决人、签锁 |
| 建 issue / 建 PR / 发 review / 打 tag / 部署前 | 看一眼再放行（可免；门不可免） |
| G3 | 裁决人判 AC、处置 B 档告警与假设台账、确认失败报告的归因层 |
| 合并 | 合并是人类动作 |
| 逃逸缺陷 | 归因到层 |

### 中断与恢复

`--resume <slug>` 从状态文件的阶段继续；账本说明上次为什么停；
评审环的水位线与计数器保证评论不重复处理、预算跨会话延续。

### 产物落在哪

```
.aidlc/<slug>/     state.json · ledger.md · notes.md · trace.jsonl     ← 运行时，不入库
.aidlc/learnings/  project.md                                          ← 晋升的规则，下轮编译
.aidlc/pr-watch/   pr-<N>.*                                            ← 评审环的水位线与计数器
specs/<slug>/      归档：状态 · 账本 · 日记 · 契约 · 锁 · 卡 · 验收 · 门记录
仓库内             cards/ · .done_when.lock · tests/<feature>/ · ratchet-log/
                   PSL-<x>.md · derived/ · dos.yaml · agent-map.md
                   CHANGELOG.md · releases/ · escape-defects.md · retro/
```

## 15. 现在还空着什么

自包含意味着也要说清楚哪里没做。

| 空白 | 现状 |
|---|---|
| 接口契约 | 没有承载。issue 的校验器只能标出"观察边界解析不了"，不能校验接口本身 |
| issue / PR 编号 | `issue.number` / `pr.number` 由引擎 set；核它们要网络，advance 不触网。评审出口已由 `pr-poll.sh` 的裁决文件核住 |
| 本体 → 代码这一向 | 制品散文里的术语漂移有传感器了；**本体改了而实现没跟上，没人检** |
| 本体版本演进 | 候选命名空间、本体自身的版本迁移没有形态 |
| Stop hook | 只有模板，不自动安装 |
| 收敛阈值 | 指纹重复次数、震荡周期、平台期轮数是先验值，还没被真实运行校准过 |
| 深度旋钮 | 只是声明，没有强制力（规则 17：如实标注，不假装） |

**证据等级：全部 skill 为 `static_only`。** 含义是结构过审 + 脚本在 fixture 上冒烟
（关键行为配变异证明：把被测的东西故意改坏，确认它真的变红）。
**带 / 不带这套纪律的行为层对照只跑过一轮**，而且出题人与被测者同源。
能说什么、不能说什么写在 `evaluation.md`——这份文档不替它下结论。

## 16. 术语

| 词 | 含义 |
|---|---|
| PSL 轨 / TASK 轨 | 形态未定（先建世界）/ 形态已定（直接进契约）；词表闭包失败是客观转轨触发 |
| AC | 验收条目，契约的最小单位；机械档（观察 / 前置 / 期望）或人判档（陈述 / 裁决人 / 证据） |
| 卡 | 自包含的任务单元；实现者的全部输入 |
| 层 | 卡 ⊂ 方案 ⊂ 任务 ⊂ 本体 ⊂ 世界，失败回流的坐标 |
| 指纹 | 失败输出的稳定摘要；同指纹重复 = 无进展 |
| 三档 | A 机械（否决）/ B 结构（告警）/ C 判断（请求人） |
| 两段锁 | G2 锁判据；测试写完后锁测试与清单 |
| 隐藏集 | 冻结判据的变体，实现者不可读 |
| 账本 / 日记 | 已经错了什么 / 含糊处当时选了什么；都只增不删 |
| 迹 | 账本的机器可读伴生，事件间用封闭集的类型边相连，因果边由效果指向原因 |
| 环契约 | 生成者 ≠ 验证者、停机四键、预算可解析 |
| 未评估 | 声明了一条判据但求值者没跑完；**不是通过** |
| static_only | 结构过审、脚本冒烟，行为层对照未充分跑 |
