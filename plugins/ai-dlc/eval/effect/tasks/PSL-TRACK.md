# PSL 轨的隐藏集怎么写

报告里登记的空白：**形态对不对没法用 pytest 判**。所以 PSL 轨一直没有题。

解法不是去判形态，是把 PSL 轨真正的失败模式拆成两半，两半都机器可判：

## 一、语义半：朴素的领域模型会被证伪

PSL 轨的典型失败是「技术正确、产品错误」——照字面实现，交出一个 `created_at` 加日历筛选器。
这**不是**形态问题，是领域模型问题，而领域模型的错误可以用行为测出来：

> 隐藏集里放几条**只有当领域模型对了才会通过**的用例。
> 朴素模型不是"少了点什么"，是**在这些用例上给出相反的答案**。

例：「按上个月搜索记忆」。朴素模型用写入时间，正确模型用事件发生时间。
一条昨天补录的、发生在上个月的记忆，两种模型给相反的结果。一条 pytest 就分开了。

## 二、判断半：不可判的部分必须被**路由**，不是被猜

剩下那部分（这个交互对不对、这个措辞好不好）确实机器判不了。但可以机器判的是：
**arm 有没有把它当成"我说了算"的事悄悄定掉。**

AI-DLC 自己的 C 档纪律就是答案：不可机械判的验收要写成 `kind: human`，带 judge 与 evidence，
路由到 G3。所以隐藏集的第二半检查产物里有没有这样一条路由记录——
有 = 它知道这里轮不到自己拍板；没有 = 它替产品经理做了决定，而且没人知道。

**这一半不判断"路由得对不对"，只判断"有没有路由"。** 前者是品味，后者是纪律。

## 每道 PSL 题的形状

| 检查 | 权重 | 判什么 |
|---|---|---|
| `test_semantics.py` | 5 | 领域模型被证伪：朴素模型在这里给相反答案 |
| `test_naive_trap.py` | 2 | 朴素实现的具体特征没有留在代码里（字段名 / 结构） |
| `test_human_routed.py` | 3 | 不可判的那部分被路由了：产物里有一条带裁决人的开放问题 |

外加两个欠定槽，与 TASK 轨同一套口径（只在 arm 新增的内容里找证据）。


## H3 的一个混淆，必须写在这里

`test_human_routed.py` 判「不可判的部分有没有被路由给人」。**AI-DLC arm 被 PROMPT 明确要求写 `ASSUMPTIONS.md`**，
那份文件天然带路由语言。所以 AI-DLC arm 在 H3 上得分高，一部分是在测量它服从自己的指令，
与欠定槽那一维是同一个混淆。

这个混淆洗不掉，只能明说，并且知道它的边界在哪：

- H1（领域模型被证伪）**不受影响**：那是行为测试，写不写台账都一样。
- H2（朴素痕迹）**不受影响**：读的是源码。
- H3 与欠定槽 **受影响**：两者都在读产物里的文字。

所以 PSL 轨真正独立的信号是 H1 + H2（权重 7），H3（权重 3）要打折读。
干净的问法是"不给 PROMPT 里的纪律段、只给它插件的脚本，它还会不会写"——那是下一轮的事。

另：H3 目前是词表匹配（两组词 AND）。它在 2026-09-06 这轮是真阴性（T07 两个 arm 确实一个字都没写谁来定），
但词表匹配随时可能重犯 E-05（把作者的措辞当成唯一答案）。**若某一轮它对所有 arm 齐红齐绿，先怀疑它，再怀疑 arm。**


## 出题人的通病（五次发作之后）

E-01 / E-05 / E-08（两处）/ E-09 是同一个错的五次发作：**出题人不自觉地把自己的实现方式写进了判据。**

| 发作 | 判据查了什么 | 该查什么 |
|---|---|---|
| E-01 | 六列加在哪个函数上（作者的读法） | 需求里说清的部分，或说清它 |
| E-05 | 源码里有没有"冲突"这个词 | 能不能推出真实上限 30 |
| E-08a | 有没有叫 `search_by_time` | 领域模型对不对（接口应在 prompt 里钉死） |
| E-08b | 源码里有没有 `priority` 这个词 | 换个插入顺序结果变不变 |
| E-09 | 推导发生在 `unread()` 里还是写入侧 | 曝光数据用没用上 |

**规律**：判据只能落在**行为**上（跑一下看结果），或落在**有没有**上（这个东西存不存在），
不能落在**怎么做**上（用什么名字、什么词、什么架构）。

**操作办法**：写完一条检查，问自己一句——「一个用完全不同写法但同样正确的实现，会不会红？」
会，就是把自己的解法当成了唯一答案，重写。
