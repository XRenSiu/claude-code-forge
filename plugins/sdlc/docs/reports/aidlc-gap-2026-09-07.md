# 对照 AWS AI-DLC 2.0：缺口、取舍、以及这一轮补了什么

> 日期 2026-09-07 · 对照对象：AI-DLC 方法论白皮书（2025-07）、开源博客（2025-11）、2.0 GA 官方文档树（2.7.x）
> 一手材料的第一手研究报告：`~/Documents/Downloads/aidlc-first-hand-report.html`
>
> 这份文档回答三个问题：**它有而我们没有的是什么**（§1）、**为什么我们决定补这些而不是那些**（§2）、
> **这一轮实际改了什么、怎么证明它真的生效**（§3）。§4 是有意不做的，§5 是这次对照顺带发现的自身 bug。

---

## 0. 先说结论

AI-DLC 的"道"是一句话：**AI 的产出速度已经超过人的验证速度，所以流程的目标函数要从「加快产出」换成
「降低验证成本」**。它的自适应 scope、深度调制、审批门禁、审计、学习闭环都是这一句的推论。

按这句话对照，sdlc 的位置是：

| 机制 | 谁更强 | 一句话 |
|---|---|---|
| 路由确定化（下一步做什么交给确定性引擎） | **sdlc** | 对面只有 next / report / park 三个子命令；这边是状态机 + routing.yaml + graph.yaml 五条 lint + loops.yaml 环契约 + 收敛检测三信号 |
| 验收前置（需求阶段就冻结的验收契约） | **sdlc** | 对面的验收散在 reviewer / sensor / 门禁三处，没有统一契约。这边有 done_when v2 + G2 哈希冻结 + 两段锁 |
| 领域本体 | **sdlc** | 对面自己承认这是它最大的结构性空缺，只能靠事后学习一次补一个词。这边有 dos.yaml |
| 学习下轮生效（可复现优先于立刻变聪明） | 平 | 对面用 BGP 类比，这边是不变量 13（提案永不自动生效）。这边还更严一点 |
| 评估者与被评估者隔离 | **sdlc** | 对面是"reviewer 不读 builder 的 memory.md"；这边有隐藏集、跨供应商分配、fix-prompt 只带位置和改法 |
| **广度旋钮**（跑哪些阶段） | **AI-DLC** | 对面 11 种 scope × 33 stage 编译成网格。这边是一条写死的 15 阶段直线 |
| **深度旋钮**（每个阶段产出多细） | **AI-DLC** | 对面三档；这边没有 |
| **测试量旋钮**（与深度正交） | **AI-DLC** | 对面三档且明确与深度解耦；这边的测试量是契约的函数，没有独立旋钮 |
| **解释日记**（含糊处当场做了什么选择） | **AI-DLC** | 对面 memory.md 四格 + 门禁逐字呈现；这边的账本记的全是**已经发生的错** |
| **审查未跑完的状态** | **AI-DLC** | 对面截断 = 门禁上可见的发现项；这边不变量 14 只覆盖脚本，不覆盖 agent |

不能信的部分：10–15 倍效率、缺陷降 40–60%、300–500% ROI，全部是 AWS 基于自己 100+ 客户实验的口径，
无独立复现。当营销读，不当证据读。

## 1. 五个真缺口

### 1.1 广度旋钮只有一档，而且数据与代码不一致

`ORDER` 是写死的 15 阶段直线（`sdlc_state.py`），`next_allowed` 原来只有一条合法跳
（G3 不需要时 review → merge）。`sizing.yaml` 的 S 档声明 `exempt: [acceptance-fleet, plan-cards]`，
但 `prereqs()` 只实现了前一项：`advance cards` 仍要 G2 pass + lock，`advance implement` 仍要
`cards.lint_passed` + 至少一张卡。**plan-cards 那半从来没生效过**——三行 bugfix 照样得写卡。

比"少实现了一项"更值得记的是：**没有任何东西会发现这件事**。`graph.yaml` 有 `graph check` 让声明与
ORDER 互相断言，`loops.yaml` 有 `verify_loop.py`，只有体量网格是一份没人核的散文。

### 1.2 分档发生得太晚

`size` 的四个输入里，AC 数要契约存在、files 要 diff 存在。`init` 时只能是 M/default。
等你能定出 S，契约和 G2 的钱已经付完了——而那正是 S 档想省的两笔里的一笔。

### 1.3 深度旋钮完全没有，测试量不是独立旋钮

AI-DLC 把三个旋钮拧开的理由很硬：「完整文档 + 最少测试」是合法组合，测试量不该被文档详细度绑架。
sdlc 这边没有"同一阶段产出多细"的档位；测试量由 `derive_counts.py` 从契约逐字读出，是 done_when 的
函数，不是可独立选择的采样率。

### 1.4 没有"解释日记"这条通道

`ledger.md` 记失败、路由、裁决、豁免；`trace.jsonl` 记类型边；ratchet 的 `learnings.md` 只活在
ratchet 环内；`/retro` 是跨 feature 的批量复盘。**全都是事后的、关于错误的**。

缺的那一条是：**规格含糊处，实现者当场做了什么选择**。`divergence.py` 抓的是事前 N 份隔离草案的
分歧，抓不到实现中途的默认填充。这正是 AI-DLC 那个 ANZ 银行例子的形状——agent 把 "transaction"
读成数据库事务，人纠正成"银行交易"——而在 sdlc 里，这次纠正发生在对话里，然后就没了。

### 1.5 reviewer 被截断没有契约

不变量 14「声明了但没求值 ≠ 通过」已经编译进 `verify_structure.py` 的 exit 3，但那只覆盖**脚本**。
六个审查 skill 和五个隔离子 agent 是 LLM：一份被截断的短报告，读起来和"没发现问题"一模一样。

## 2. 为什么补这五个，而不是补别的

对照报告里还有五六条可抄的东西，这一轮没抄，理由分两类。

**已经有等价物，抄了是重复**：agent 之间禁止互调（五个子 agent 的 tools 里本来就没有 Task）；
学习下轮生效（不变量 13 更严）；确定性 sensor 作为第二意见（A 档一票否决比对面"全建议性、不阻断"强）。

**与本插件的取舍冲突，有意不抄**：把 sensor 挂成 PostToolUse hook。`design-notes.md` 写得很清楚——
挂 PreToolUse 会拦所有 git commit，对非 sdlc 场景过填，留给用户按仓库决定。这条不是缺口，是取舍。

补的这五个的共同点：**它们都落在"人的验证成本"上**，也就是 AI-DLC 那句话本身。广度与深度旋钮降低
一次交付要人看几遍；解释日记把含糊处的选择变成人能一眼扫过的清单；reviewer 截断契约防止人把
"没跑完"读成"没问题"——那是验证成本被静默转嫁的最坏形态。

## 3. 这一轮改了什么

### 3.1 广度网格（`sizing.yaml` v2 + `verify_sizing.py`）

`stages:` 网格取代原来只有散文的 `exempt:`，成为唯一的源。`never_skippable` 把"哪些阶段任何档都不能跳"
写成数据——**三道门在里面**。`effective_skips()` 三重保险：档位必须是推导来的、阶段不在 never_skippable 里、
每条 skip 必须有 why。`next_allowed` 与 `prereqs` 按网格放行，`advance` 为每个被跳的阶段写一条有类型的
`size_exemption` 账本行（带理由），`/retro` 照旧按档分桶数逃逸缺陷。

`verify_sizing.py` 七条 lint，其中 L7 直接 `import sdlc_state` 用真的那份 `next_allowed` 把每一档的
剩余路径走一遍——一个自己写的第二份 next_allowed 迟早与真的那份分叉，而分叉出来的那份会说"网格没问题"。

**极性原样保留**：`set intake.size=S` 把来源打成 manual，一扇门也打不开。

### 3.2 早定档 + 飞行中重定档

`size --from-issue <body.md>` 从 `verify_issue.py` 的 `acceptance_stats` 取 AC 数——数字和它的来路由
同一次读产生，issue 没过 verify_issue.py 就拒绝取数。`--early` 允许在还没有 diff 时定档，来源记成
`derived_early`。

这里有一条**落出来的**性质，不是额外加的限制：S 的唯一入口 SZ-05 需要 files，而缺一个量的规则不会
命中，所以**早定档在结构上只能把你推向 L 或留在 M，永远给不出 S 的豁免**。`sizing.yaml` 的 `needs:`
字段把这件事写成声明，`verify_sizing.py` L6 核它与 `when:` 一致——从注释变成可证的性质。

重定档只能改尚未开始的阶段：落在当前阶段身后的 skip 一律丢弃并记 `size_recompose`。一次已经付过的
G2 不会因为重定档被追认为"其实不用签"。

### 3.3 深度与测试量两个旋钮

`tiers.<档>.depth` 与 `tiers.<档>.test_strategy` 正交声明。**诚实标注强制力不同**：广度由
`next_allowed` / `prereqs` 强制；测试量是下界，由 `derive_counts.py --strategy` 检（exit 4，与"空
behavior"的 exit 2 分开——一个是量不够，一个是配置错）；**深度只是声明给 skill 读的输入，没有脚本能
判"这份文档够不够细"**，文档里就这么写，不假装它是闸。

minimal 档的地板照抄了奈奎斯特那个类比，但地板从契约算不从策略名猜：
`minimal = mechanical AC 数（每条需求一个采样点）+ 观察边界数（每个边界一条 happy path）`。
comprehensive 不设算术地板——它的下界是"五层金字塔每层都非空"，那是判据，不是一个数。

### 3.4 解释日记（`notes.md` 四格）

`note --kind interpretation|deviation|tradeoff|open_question` 追加，只增不删。
`notes --for-gate <g>` 是门禁仪式：**逐字呈现每一行，不改写、不做「有趣度」筛选**，外加那条永远会问的
自由文本通道。签字人唯一要做的分类是"哪几条该变成下一轮的规则"。

四格的分法照抄，因为它分得对：前三格是可固化的知识，**Open questions 明确不晋升**——它是研究项不是
规则，脚本硬拒。作用域只有 `project`，**没有 team / org 通道**（也照抄；提升是人在仓库之间做的事）。

晋升状态记在 `state.notes.promoted`，所以晋升**不用回头改写日记的任何一行**——日记保持只增不删。

**下轮生效**：`init` 读 `.sdlc/learnings/project.md`，记下路径 + 内容哈希 + 条数。跑动中晋升的规则不
影响本轮。冒烟用例直接断言这条性质：产出规则的那次运行 `state` 里没有 `learnings`，下一次 `init` 有。

### 3.5 自治阶梯 + 跳过的三选一

`autonomy --level ask_each|auto_until_gate|auto_until_failure --by <人>`：整个流程只问一次，答案记进
state，`--resume` 之后仍然有效。与原来的 `--autopilot` 的差别是它**不是一个 CLI flag**——flag 每次调用
都要重给，恢复会话就丢；记进 state 的答案跨会话活着，而且能被 `/retro` 数。三档都不改门。

`card --status skipped --reason <必填>` 是失败三选一里的"跳过"，并**当场列出声明了 `depends_on` 它的卡**
——跳过的代价不落在被跳的那张卡上，那句警告必须当场给，而不是等它们一张张红给你看。

### 3.6 `plan` 与 `doctor`

`plan` 在启动前从网格算出这次跑几个阶段、几道人签的门、跳了什么、为什么跳、深度与测试量是哪档。
档位没推导时它明说"一个阶段也跳不掉"，而不是让人以为自己在走轻量路径。

`doctor` 查装置健康度（pyyaml、脚本齐不齐、三个 lint、git/gh、Stop hook 装没装）。
**建议性，从不阻断**，也不进 `advance` 的前置条件——一个会阻断的 doctor 会变成第四道门，而这个插件
只有三道门。

### 3.7 reviewer 截断契约与跨制品术语 sensor

见 `skills/acceptance-fleet/scripts/verify_review_complete.py` 与
`skills/dos-extract/scripts/verify_vocabulary.py` 各自的 docstring；接线见 §7 的覆盖矩阵。
前者把不变量 14 从脚本扩到 agent；后者把本体从"只在 issue 的一个字段上跑一次"扩成跨制品的 B 档 sensor。

## 4. 有意不做的

- **不挂 PostToolUse / PreToolUse hook**：`design-notes.md` 的旧决定不变，Stop hook 仍然只有模板。
- **不加第四道门**：走通骨架的早期信心检查点没有做成 gate。AI-DLC 的坑一修法里那一半与本插件的
  "三道门 ≠ 五个 human 节点"直接冲突，加一道有 verdict 的门是架构变更，不是补缺口。这一轮只做了
  阶梯与三选一那一半。
- **不做 team / org 规则层**：AI-DLC 的五层链（org → team → project → phase → stage）与严格叠加 +
  准入时冲突检查是配套的；只做层不做冲突检查会得到一个"规则互相矛盾时看谁读得晚"的系统。
  这一轮只做最窄的 project 层。多层与冲突检查是同一件事，要做一起做。
- **不解析 issue markdown 数 AC**：`verify_issue.py` 已经解析并校验了那个块，它的 `acceptance_stats`
  就是权威。第二个解析器迟早与它分叉，而分叉出来的那个数会被用来换豁免。

## 5. 这次对照顺带发现的自身问题

| # | 问题 | 影响 | 处置 |
|---|---|---|---|
| A-01 | `sizing.yaml` 声明 S 档 exempt 两项，`prereqs()` 只实现一项 | 数据承诺的轻量路径引擎没兑现，且无人发现 | §3.1 网格 + `verify_sizing.py` |
| A-02 | 体量网格没有任何 lint，`graph.yaml` / `loops.yaml` 都有 | 同类资产三份，只有一份没人核 | `verify_sizing.py` 七条 |
| A-03 | 「走到 acceptance 再空手离开」不留任何记录 | S 档进了验收阶段却没产物就去 pr，网格放行且无账本行；`/retro` 的分桶会漏计 | `cmd_advance` 补了这一支；**是既有冒烟用例抓到的**，不是读出来的 |
| A-04 | `advance pr` 不检 `pending.failure_report` | 原来这道检查只在 `advance acceptance` 上，acceptance 被跳过时它整个消失 | `prereqs("pr")` 补上 |

A-03 值得单记：它是**本轮改动引入的回归**，被 v0.10.0 留下的一条既有用例当场抓住。那条用例的
setup（手改 stage 到 acceptance 再 advance pr）在网格语义下测的是另一个场景，而正是那个场景暴露了
新代码的洞。**一条看起来"该更新一下"的旧用例，先假设它在说一件你没想到的事。**

## 6. 怎么验

```bash
# 网格自身
python3 plugins/sdlc/skills/sdlc/scripts/verify_sizing.py

# 这一轮的全部新用例（13 条网格 + 5 条日记 + 4 条自治/卡/plan/doctor + 3 条测试量地板）
bash plugins/sdlc/eval/smoke.sh --only 'sizing|grid|notes|autonomy|card --status|plan on|doctor|derive_counts|promot|early|hand-set|recompose|append-only|NEXT run|open question'

# 全套
bash plugins/sdlc/eval/smoke.sh
```

证据等级仍然是 `static_only`：脚本在 fixtures 上冒烟，**带 / 不带这些改动的行为层对比没跑**
（`eval/effect/` 的题库是十题，这一轮没有为广度网格出题）。按 `docs/evaluation.md` 的三层证据，
这一轮能说的是"网格与代码互相断言且极性守得住"，**不能说**"分档定得对"——分档对不对由下一次逃逸
缺陷回答，不由 lint 回答。
