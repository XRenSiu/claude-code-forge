# 拆卡启发式

## 按什么拆（优先级从高到低）

1. **按观察边界**：一个 `observe`（route / cli / ui / db_field / event）一张卡——AC 子集天然成组，验收对象清楚。
2. **按 DOS 对象**：一个聚合根及其关系一张卡；跨对象的行为放在拥有主对象的卡。
3. **先契约后 UI**：接口 / 数据形态的卡先做（其他卡 `depends_on` 它），UI 卡后做。
4. **生成物单独**：schema 生成、lockfile、迁移脚本单独一张卡，或全部禁改。
5. **投影与其数据源同卡**：渲染 / 报告脚本与它读的那份数据在同一张卡。这条优先于按文件归属切——
   见下节，`lint_cards.py` 会查。

## 投影与数据源必须同卡

> 本次 dogfood 的两轮修复各有 2/6 条发现是"修复自己引入的"。扫描窗口在 `replay_card_commits.sh`（CARD-01），
> 那个窗口的标签与列表在 `render_audit.py`（CARD-06）。两张卡，没有任何一个实现者能原子地同时改数据源与
> 它的投影，于是标签与窗口在两轮里各错一次。切卡按"文件归属"切时，这条接缝是看不见的。

**判据**：一段代码的全部职责是呈现另一段代码产出的数据（渲染、报表、摘要、图表、导出），
那么它和它读的数据属于同一张卡。理由不是审美——**是原子性**：数据的形状与它的标签必须能在一个 commit 里
一起改，否则每次改一侧都要赌另一侧的实现者读到了同样的意思。

**卡上怎么写**（`lint_cards.py` 检查项 6）：

- 卡的 `allowed_files` 里有渲染 / 报告脚本时，**必须**声明 `reads_from:`（列出它读的数据文件；
  空列表 = 不读任何别的卡拥有的东西）。不写就是 REJECT——这正是没人写下来的那一项。
- `reads_from` 里的每个路径：
  - 本卡 `allowed_files` 覆盖它 → 原子情形，通过；
  - 别的卡拥有它 → 必须 `depends_on` 那张卡，**并且** `notes` 写明接缝风险（只改一侧会坏成什么样）。
    两项缺一即 REJECT；
  - 没有卡拥有它 → 外部输入，记 info。
- 给了 `--repo-root` 时，脚本本身也会被读：源码里出现的路径字面量若被别的卡拥有而 `reads_from` 没声明，
  按"未声明的接缝"拒。声明因此是可核验的，不是自述。

`--projection-pattern` 可改判定投影的 basename 正则（默认 `render|report|dashboard|chart|plot|summary|digest`），
只对**字面量脚本路径**生效——`src/views/**` 这种目录 glob 不会被误判。

## REQ 粒度受 L4 反压（G2 前拆最便宜）

L4 的两条硬规则——**一个 REQ 只能归一张卡** 与 **单卡上下文 ≤ 40k**——合起来对**契约层的 REQ 粒度**
构成反压：一个 REQ 若其实现读集超过 40k，它就没有任何合法拆法（拆卡会让两张卡共同拥有它，违反第一条；
不拆则违反第二条）。

**所以在 G2 冻结之前就要问**：每个 REQ 的实现读集能不能装进一张 ≤ 40k 的卡？装不下就在契约层按分区把
REQ 拆开，别等到切卡时才发现。本次 dogfood 正是在卡已经开始切的时候才撞上这条，只好回头补 REQ-008..011，
赶在 G2 冻结前塞进契约。**G2 之后再拆要走变更提案 + 重新签锁**，贵一个数量级。

估算读集用下一节的公式，粗算即可；判断的是量级，不是小数点。

## 共享文件处置

| 文件 | 默认 |
|---|---|
| package.json / lockfile / go.mod / Cargo.toml | 归"依赖卡"一张；其余卡 forbidden |
| 路由表 / DI 容器 / 配置 | 归拥有最多新路由的卡；其余卡 forbidden，需要加路由的卡在 `notes` 写清让它代加 |
| tests/** | 全部卡 forbidden（非实现者写、写完锁） |
| done_when.yaml / dos.yaml / .done_when.lock | 全部卡 forbidden |

## 上下文估算（粗算即可，但要诚实）

`估算 ≈ 卡本身 1k + AC 子集 × 0.3k + allowed_files 内源码 token + 相关测试 token + DOS 切片 1k`。
用 `wc -c` 除以 3.5 近似 token。> 40k 拆；20–40k 可接受；< 5k 可能拆过细（合并）。

## 反模式

- 一张"其余所有"的卡（`src/**`）。
- 卡 A 的 `notes` 说"参考卡 B 的实现"——卡不能互相引用实现，只能 `depends_on` 顺序。
- 把验收写成"跑全部测试"——卡级只跑 `ac_ids`，整体验收在 fleet。
- 渲染脚本一张卡、它读的数据一张卡——见上一节；这是本次两轮修复里 4 条发现的共同根因。
- 为了让某个 REQ 塞进 40k 而把它拆成两张卡共同拥有——违反"REQ 一卡一主"。该拆的是 REQ，不是归属。
