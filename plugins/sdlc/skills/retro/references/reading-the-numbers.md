# 读数：解读与常见误读

- **回流分布**：看比例不看绝对值。card 层高是正常（那是最便宜的层）；task 层高 = 判据常写错 → 看 AC 收紧；
  ontology / world 层 > 0 就逐条读账本——每条都值一次 G1 复盘。
- **G1 拦截率**：高不一定坏。"推错了"多 = 推导者弱或 PSL 欠定（看分歧集）；"规律错了"多 = PSL 需要改，这是它的用处。
- **human AC 占比**：> 0.5 持续 = 这类需求走不了机械验收，别硬走；< 0.1 = 可能把该人判的写成了假机械判据（看 expect 是否真可观测）。
- **PR 返工轮次**：先看 verdict 分布——REJECT 多 = reviewer 与契约不一致（契约没被 reviewer 读到？Scope 段写清了吗）；
  ACCEPT 多 = 实现前测试没覆盖（回 test-suite-generator）。
- **逃逸缺陷**：每条看 `why_gate_missed`；同一原因 ≥ 2 次 = 门要改，不是人要小心。
- **豁免**：`--force` 是合法的紧急出口，但每条要有理由；理由重复出现 = 前置条件定错了。
- **lead time**：单独没意义；与轮次、豁免一起看。刻意切小任务会压低它，同时抬高逃逸率——两个一起看。
- **样本 1**：只记基线。
