# eval/effect — 带 / 不带 skill 的行为层对照

这个目录存在的唯一理由：sdlc 的 28 个 skill 全部 `static_only`。脚本在 fixture 上冒烟过，
但「**带 sdlc 的 agent 交付是不是比不带的好**」一次都没测过，所有闸门阈值都是文献先验。
一个声称抬高下限的插件，自己没有下限的测量值——这是报告 `docs/reports/raising-the-floor-2026-09-05`
排在第一位的缺口。

## 三个 arm

| arm | 拿到什么 | 对应业界的什么 |
|---|---|---|
| `bare` | 只有需求。fixture 里连 CLAUDE.md 都删掉 | 裸 agent |
| `claudemd` | 需求 + fixture 自带的 CLAUDE.md | 业界默认做法（2607.27250 测得对正确率无可测量影响） |
| `sdlc` | 需求 + CLAUDE.md + sdlc 的纪律与脚本 | 判据先写、阈值要有来源、假设进台账 |

**三个 arm 的需求文本逐字相同。** arm 之间的差别只能是上下文与纪律，不能是题面。

## 怎么跑

```bash
python3 run.py prepare T01 --arm bare     --workdir /tmp/eff   # 物化，产出 PROMPT.md
#   把 PROMPT.md 交给这个 arm（新会话、只能看这个目录），让它干完
python3 run.py collect T01 --arm bare     --workdir /tmp/eff   # 隐藏集进场，收分
python3 score.py --workdir /tmp/eff --out baseline.md
```

## 三条不可协商的纪律

1. **隔离**：`prepare` 出来的目录里没有 `hidden/` 的任何字节（脚本对此有断言）。arm 看得到隐藏集 = 这次运行作废。
2. **机器判**：分数来自隐藏集的 pytest 与欠定槽的模式匹配，不来自评委的印象。LLM 只在 arm 里干活，不在评分里说话。
3. **拒绝下结论**：`score.py` 编译了 `MIN_TASKS = 5` 与 `NOISE_BAND = 0.15`。样本不够或差距落在带内，
   verdict 就是 `insufficient_sample` / `within_noise`。**这条是给写这个目录的人设的**——一次运行就宣称插件有效，
   正是这个插件自己批评的那种错。

## 每个任务测什么

隐藏集分两半，这是设计的核心：

- **需求写清楚的那半**：六列、顺序、别动已有行为。三个 arm 都该做对。
- **需求没写清楚的那半**：空值怎么写、「快」是多少。**任选一种都算对，但必须前后一致、且在产物里写明选了哪种。**
  这是「信息补足」的机器可判形态：silently guess 的实现会在一致性或无记录上露馅。
  Ambig-SWE（ICLR 2026）说模型分不清任务写没写清楚，所以不能问 arm「你觉得这里模糊吗」，只能看它留下了什么。

## 第二轮运行（2026-09-06，T01–T05 × 3 arm，15 次）

结果在 `baseline.md`。**两个维度分开判，因为它们的结论不一样**：

| 维度 | bare | claudemd | sdlc | 判决 |
|---|---|---|---|---|
| 隐藏集（做对了没有） | 0.94 | 0.94 | 1.00 | `within_noise`（差 0.06，带宽 0.15） |
| 欠定槽（没写清楚的地方写下来了没有） | 0.50 | 0.60 | 1.00 | `sdlc_leads`（差 0.50，超带宽） |

这个形状与 arXiv 2607.27250 的 288 次运行一致：**上下文策略不移动正确率**。
五道题里三个 arm 几乎都做对了（模型本来就强），分开它们的不是「做没做对」，
是「需求里没说清的地方，有没有留下痕迹」。那正是报告里排第一的那个变量。

**必须同时说的三条**（否则这张表会被读成"sdlc 有效"的证明）：

1. **sdlc arm 被明确要求写台账**，它在槽这一维得分高，一部分是在测量它服从自己的指令。
   这个混淆没法从数据里洗掉，只能明说。真正干净的问法是"不给它 PROMPT 里的纪律段、
   只给它插件的脚本，它还会不会写"——那是下一轮的事。
2. **出题人与被测者同源。** 五道题是我写的，隐藏集也是我写的。
3. **n=5**，15 次运行全部收完。`MIN_TASKS=5` 是能出判决的最低线，不是可靠的线。

> 收分时序的事后核对：`T01-sdlc` 与 `T04-sdlc` 收分时，运行时列表还把它们显示为 running。
> 逐条比对时间戳后确认，两次收分（13:45:56 / 13:47:04）都在它们各自报完成之后（13:44:15 / 13:45:52）——
> 列表状态是滞后的，不是收早了。两个 arm 都在完成报告到达后重收了一次，分数一字未变（10/10、2/2）。
> 这次核对本身就是 E-03 留下的规矩：**收分早于 arm 完成，这一轮就不算数**，所以它不能靠印象判断。

### 第二轮抓到的新问题

| # | 发现 | 处置 |
|---|---|---|
| E-05 | T03 的「矛盾有没有写下来」检的是**用词**不是实质：三个 arm 全红，其中 sdlc arm 把矛盾写得很透（「张力」「上限是 30」「永远不会成为约束」），只是没用正则里的词。与 E-01 同类——把作者的措辞当成唯一正确答案 | 改成检实质：能不能推出真实上限 30（那个数只有注意到两条规则相互作用才推得出来），或明说互相咬。改后 sdlc 10/10，bare / claudemd 仍 7/10，未干活的基线仍 3/10 |
| E-06 | 欠定槽的证据曾在**整份文件**里找，fixture 自带的 CLAUDE.md 与注释就能命中——一个没干活的 arm 也能拿 2/2 | 改成只在 arm **新增的内容**里找。十道题的未干活基线现在槽全部为 0 |
| E-07 | `score.py` 只判隐藏集一个维度，会把唯一分开的信号（槽）藏起来 | 两个维度分开判，各用同一条噪声带与样本下限 |

## 十道题跑完之后（2026-09-06，30 次运行）

**结论要先泼冷水**：把受混淆的维度剥掉之后，三个 arm 分不开。

| 维度 | bare | claudemd | sdlc | 差距 vs 噪声带 0.15 |
|---|---|---|---|---|
| 全部十道 · 隐藏集 | 0.80 | 0.80 | 0.94 | 0.14，**带内** |
| 全部十道 · 欠定槽 | 0.55 | 0.60 | 0.95 | 0.40，超出 |
| TASK 轨 · 隐藏集 | 0.94 | 0.94 | 1.00 | 0.06，带内 |
| PSL 轨 · 隐藏集 | 0.66 | 0.66 | 0.88 | 0.22，超出 |
| **PSL 轨 · 只看 H1+H2**（去掉受指令混淆的 H3） | **0.94** | **0.94** | **1.00** | **0.06，带内** |

最后一行是最该看的一行。H3（不可判的部分有没有交给人）与欠定槽这两维，
sdlc arm 的 PROMPT **明确要求**它写台账——那两维部分在测量它服从自己的指令。
把它们剥掉，只留领域模型有没有被证伪、朴素痕迹在不在：**33/35 · 33/35 · 35/35**，
三个 arm 落在噪声带内。

### 两条站得住的观察

1. **CLAUDE.md 在十道题上没有产生任何可测量的差别。** bare 与 claudemd 在每一个维度上同分：
   TASK 轨 0.94/0.94、PSL 轨 0.66/0.66、H1+H2 都是 33/35。唯一的差是欠定槽 0.55 vs 0.60——
   二十个槽里多写了一个。这与 2607.27250 的 288 次运行一致，而 CLAUDE.md 正是业界默认做法。
2. **分开三个 arm 的是「写没写下来」，不是「做没做对」。** 但那一维恰好是 sdlc arm 被明确要求做的事，
   所以它证明的是"要求写台账，就会写台账"，不是"这套纪律让人做得更好"。

### 干净的下一步（本轮没做）

不给 sdlc arm 的 PROMPT 那段纪律，只给它插件的脚本，看它还会不会写台账。
那才能分开"服从指令"与"纪律内化"。这一轮做不到，因为纪律段就是 arm 定义的一部分。

## 第三轮运行（2026-09-06，T06–T10 × 3 arm，PSL 轨）

PSL 轨的十五次运行。**这一轮的主要产出又是题目 bug**——三处，都是同一个病：

| # | 发现 | 影响 | 处置 |
|---|---|---|---|
| E-08a | T06 的隐藏集按 `search(phrase, today)` 探测，而 arm 的签名是 `search(query, when, today)`，参数错位 | T06-claudemd 领域模型完全正确却判 2/10 | 接口钉死在 prompt 里（PSL 题测领域模型，不测接口命名），改后同一个 arm 7/10 |
| E-08b | T10 的检查要求源码里出现 `priority` 这个词 | T10-claudemd 用置顶时间排序（确定、可控、不看运气）判 0/10 | 「不看运气」改写成性质：同一组置顶换个插入顺序结果必须一样。改后 7/10 |
| E-09 | T08 的检查要求「不能在 `unread()` 里读布尔」 | T08-sdlc 用写时更新的闩锁，曝光数据确实用了，只是推导在写入侧，判 8/10 | 只判用没用，不判在哪用。改后 10/10 |

**改题的代价，记在账上。** T06 与 T10 的三个 sdlc arm 是按 revision 1 的提示跑的，
它们的产物**没有收分**：用 rev2 的判据去评一个从没见过 rev2 提示的 arm，是拿两把不同的尺子比。
（run3 的 T10-sdlc 做的事本身是对的——它先在原实现上复现了「看运气」：同一批帖子换个添加顺序，
返回从 `[1,2,3,4]` 变成 `[2,1,4,3]`——但那次运行只能作为定性记录，不进表。）

**五次同类发作之后，这条规律写进了 `tasks/PSL-TRACK.md`**：判据只能落在行为上或「有没有」上，
不能落在「怎么做」上。写完一条检查要自问——一个用完全不同写法但同样正确的实现，会不会红？

## 第一轮运行（2026-09-06，T01 × 3 arm）

结果在 `baseline.md`。verdict 是 `insufficient_sample`——1 个任务，下限是 5。

**这一轮的主要产物是题目自己的两个 bug，不是 arm 的排名。** 记在这里，因为它们决定了这批数字怎么读：

| # | 发现 | 处置 |
|---|---|---|
| E-01 | H1（六列）把一种读法写死成唯一正确答案。`claudemd` 读了 CLAUDE.md 的「已有接口的行为不要改」，于是**新加**一个六列函数、保留原三列函数——这是对需求的合法读法，却被判 0 分。隐藏集在惩罚「没跟我猜得一样」，不是在惩罚差实现 | T01 的 prompt 需要点明六列加在哪个函数上；`claudemd` 这一轮的 5/10 **不能读作它更差** |
| E-02 | 欠定槽 U1 的证据模式比隐藏测试 H2 窄，同一件事一个说写了、一个说没写（`bare` 在 docstring 里写了「缺列」怎么处理，H2 认、U1 不认） | 已修：两处用同一个模式集，重收后 `bare` 的槽分从 0/2 变 1/2 |
| E-03 | **铁律 1 只写在文档里，没有编译。** `collect` 把隐藏集直接铺进 arm 的工作区，而我在 `sdlc` arm 还在干活时就跑了 collect——它最后那次 pytest 把 5 个隐藏测试一起跑了（是那个 arm 自己读源码后报上来的，它自陈没读隐藏测试的内容）。写在 README 里的纪律不是纪律 | 已修：`collect` 在**副本**里评分，绝不碰 arm 的工作区；泄漏与否由 mtime 机械判定（泄漏晚于 arm 全部产物 = 它没机会读到），被判污染的结果不计入均值但**留在报告里**。`sdlc` 的这一轮因此作废 |
| E-04 | `validate_done_when_v2.py` 里我新加的结构层校验用了 `names` 这个变量名，覆盖掉上面算好的测试名清单，于是 `tests_in_manifest` 报的是层数不是测试数 | 已修 + 冒烟孪生锁死（同一份契约声明 / 不声明 structure，测试计数必须相等）。**这条是 sdlc arm 读插件源码发现的**——被测者反过来抓到了测量者的 bug |

数字（改口径后重收）：

| arm | 隐藏集 | 欠定槽 | 备注 |
|---|---|---|---|
| bare | 10/10 | 1/2 | 写了空值策略，没给「快」的阈值 |
| claudemd | 5/10 | 1/2 | 见 E-01，这个分数口径有问题 |
| ~~sdlc~~ | ~~10/10~~ | ~~2/2~~ | **作废**（E-03 污染）。它交出的 `ASSUMPTIONS.md` 把两个欠定槽都写成了带风险与验证人的假设、并拒绝编造绝对时延——但这一轮的数字不算数，要算得重跑 |

**能说的只有一句**：harness 跑通了，四个 bug 被这一轮抓出来（两个在题目里、一个在 harness 自己的纪律上、一个在插件源码里）。
其余一律不能说，直到 ≥ 5 个任务且没有污染。
